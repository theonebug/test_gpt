# OCR-утилита: распознавание сканов старого руководства (RapidOCR)

> **Файл:** `util/ocr_scan.py` · **Назначение:** офлайн-OCR сканов руководства
> старого регулятора с сохранением текста в файл.

---

## 1. Что это

Скрипт выполняет **распознавание текста (OCR)** на изображениях-сканах
руководства по эксплуатации старого регулятора (`docs/1.jpg` … `docs/4.jpg`)
и складывает распознанные строки в один текстовый файл `docs/scan_text.txt`.
Полученный текст использовался как «эталон стиля» при вёрстке нового руководства
`docs/OPERATING_MANUAL.html`.

Ключевая особенность — **полностью офлайн-работа**: движок RapidOCR
(ONNX-модели) не отправляет данные в интернет и не требует API-ключей.

---

## 2. Как это работает (архитектура)

```
┌─────────────┐   ┌──────────────┐   ┌──────────────────┐   ┌────────────────┐
│ 1..4.jpg    │ → │ RapidOCR     │ → │ сортировка строк │ → │ scan_text.txt  │
│ (сканы)     │   │ (ONNX-модели)│   │ по координате Y  │   │ (отчёт)        │
└─────────────┘   └──────────────┘   └──────────────────┘   └────────────────┘
```

**Пошагово:**

1. **Инициализация.** При запуске создаётся экземпляр `RapidOCR()`.
   При первом запуске библиотека скачивает ONNX-модели в кэш пользователя,
   последующие запуски работают уже из кэша.
2. **Обход изображений.** Скрипт проходит по четырём файлам — `1.jpg`, `2.jpg`,
   `3.jpg`, `4.jpg` — из каталога, где лежит сам скрипт (`BASE`).
3. **Распознавание.** `engine(img)` возвращает кортеж `(result, elapsed)`, где
   `result` — список `(box, text, score)`:
   * `box` — 4 точки рамки текста на изображении;
   * `text` — распознанная строка;
   * `score` — уверенность распознавания (0…1).
4. **Сортировка строк.** RapidOCR возвращает строки в порядке обхода алгоритма,
   поэтому для читабельности строки сортируются **сверху вниз по координате Y**,
   а при равном Y — слева направо по X:
   ```python
   rows = sorted(result, key=lambda r: (r[0][0][1], r[0][0][0]))
   ```
5. **Формирование отчёта.** Для каждой строки в `scan_text.txt` пишется
   `[y=NNNN] текст` — Y-координата верхнего края рамки. Это позволяет
   восстанавливать вёрстку исходного документа (заголовки, таблицы, колонтитулы).
6. **Кодировка.** Результат сохраняется в UTF-8.

## 3. Зависимости

| Пакет | Зачем | Установка |
|---|---|---|
| Python 3.8+ | среда выполнения | `winget install Python.Python.3.12` |
| `rapidocr_onnxruntime` | OCR-движок | `python -m pip install --user rapidocr_onnxruntime` |
| `onnxruntime` | зависимость RapidOCR (ставится автоматически) | — |

> **Не требуется:** pytesseract, Tesseract-OCR, GPU, интернет после первого
> запуска (модели кэшируются).

## 4. Запуск

```powershell
# 1. Установить зависимости (один раз)
python -m pip install --user rapidocr_onnxruntime

# 2. Положить скрипт рядом со сканами (1.jpg ... 4.jpg) либо поправить IMAGES
#    В проекте: docs/ocr_scan.py при docs/1.jpg ... docs/4.jpg

# 3. Запустить
cd docs
python ocr_scan.py
```

**Вывод в консоль:**
```
Готово, результат в: C:\...\docs\scan_text.txt
```

**Выходные коды:** `0` — успех; ненулевой (через `sys.exit`) — RapidOCR не установлен.

## 5. Структура отчёта `scan_text.txt`

```
============================================================
ФАЙЛ: 1.jpg
============================================================
[y=0128] РУКОВОДСТВО ПО ЭКСПЛУАТАЦИИ
[y=0284] Устройство управления углом включения
...
```

* Разделитель `===` отделяет результат по каждому скану.
* `[y=NNNN]` — Y-координата рамки текста (в пикселях скана).
* Если файл не найден — `[файл не найден]`; если текст не распознан —
  `[текст не распознан]`.

## 6. Ограничения и известные особенности

| # | Ограничение | Комментарий |
|---|---|---|
| 6.1 | Порядок строк таблиц | RapidOCR читает по блокам; ячейки могут «перемешиваться» — восстанавливать вёрстку таблиц по Y-координате нужно вручную |
| 6.2 | Тире/кавычки | Модели иногда путают длинное и короткое тире, «ёлочки» с прямыми кавычками |
| 6.3 | Не распознаёт рукописный текст | только печатный |
| 6.4 | Первый запуск медленный | скачивание и прогрев ONNX-моделей (десятки секунд) |
| 6.5 | Y-координата относительна | при разных DPI сканов Y сравнивать можно только внутри одного файла |
| 6.6 | Имена файлов захардкожены | список `IMAGES` правится в коде — аргументов CLI нет |

## 7. База знаний: ответы на частые вопросы

**Q: Почему RapidOCR, а не Tesseract?**
A: RapidOCR даёт лучшие результаты на кириллице «из коробки» и не требует
установки внешнего бинарника (Tesseract нужно ставить отдельной программой
и настраивать PATH).

**Q: Куда ставятся модели?**
A: ONNX-модели попадают в кэш пользователя при первом запуске пакета
`rapidocr_onnxruntime`; далее работают офлайн.

**Q: Как добавить пятый скан?**
A: В коде в строке `IMAGES = [os.path.join(BASE, f) for f in ("1.jpg", ...)]`
добавить `"5.jpg"` в кортеж.

**Q: Как распознать PNG вместо JPG?**
A: RapidOCR работает через OpenCV, поддерживает PNG/BMP/JPEG — достаточно
изменить список `IMAGES`.

**Q: Скрипт падает с «RapidOCR не установлен» — что делать?**
A: `python -m pip install --user rapidocr_onnxruntime` и повторить запуск.
Если пакет стоит, но скрипт его не видит — проверить интерпретатор:
`python -c "import rapidocr_onnxruntime; print('ok')"`.

**Q: Как получить текст без Y-координат?**
A: В коде заменить формат на `out.write(text + "\n")` либо отфильтровать вывод:
`Select-String -Path scan_text.txt -NotMatch '^\[y='`.
