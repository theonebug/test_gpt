# Изменение: FIRST WAVE — пропуск последующих полуволн (PassThrough)

**Ветка:** `fix/first-wave-passthrough`
**Коммит:** `a83db14` — `fix(first-wave): propuskat posleduyushchie poluvolny, otkryvaya tiristor srazu posle nulja (PassThrough)`
**Автор:** theonebug · **Дата:** 14.09.2026
**Статус:** реализовано, запушено, компиляция в CubeIDE 2.2.0 (0 ошибок, 0 предупреждений `-Wall`).

---

## Суть изменения

Изменена логика работы режима **FIRST WAVE** («срез первой полуволны»).

**Было.** Управляющий импульс по заданному углу подавался **только на первой полуволне**,
а на последующих полуволнах тиристор вообще не трогался. Физически этого недостаточно:
тиристор (симистор) запирается при каждом переходе тока через ноль, поэтому при отказе от
повторного открытия последующие полуволны не проходят.

**Стало.** Импульс подаётся на **каждой** полуволне, но его форма зависит от номера волны:

- **1-я полуволна** — обрезается по заданному углу (фазе включения), как и раньше;
- **2-я и последующие полуволны** — тиристор открывается **сразу после перехода через ноль**
  (режим *PassThrough*), т.е. волна проходит **без среза по углу** и без искажений до конца
  заданного времени работы.

> Остальные два режима — **CONTINUOUS** и **TIMED** — работают **без изменений**:
> срез по углу выполняется на каждой полуволне.

---

## Причина внесения

Физика работы тиристора: после открытия ток течёт до естественного спада до нуля, после
чего тиристор **закрывается**. Следовательно, чтобы ток проходил и в последующих
полупериодах, тиристор нужно **заново открывать** на каждом переходе через ноль.

Прежняя логика («импульс только на первой полуволне, следующие не трогаем») в реальной
схеме приводила к тому, что после первой полуволны тиристор оставался закрытым, и энергия
на нагрузку не поступала. Новое поведение устраняет это:

1. **Старт остаётся дозированным** — первая полуволна по-прежнему ограничивается заданным
   углом (плавное/мягкое включение, без резкого стартового броска);
2. **Передача мощности сохраняется** — начиная со второй полуволны тиристор открывается
   сразу после нуля, волны проходят без среза, что даёт максимум мощности на нагрузке;
3. **Старые режимы не ломаются** — CONTINUOUS и TIMED не используют PassThrough и ведут себя
   как раньше.

## Реализация

### 1. Новый флаг состояния тиристора — `Core/Device/tiristor.h` / `tiristor.c`

Добавлен признак `PassThrough` в структуру `TiristorControl_t` и парные функции:

```c
void    Tiristor_SetPassThrough(uint8_t pass);
uint8_t Tiristor_GetPassThrough(void);
```

- `Tiristor_Init()`: инициализируется `Tiristor.PassThrough = 0`.
- Комментарий в `tiristor.h` фиксирует смысл: тиристор открывается сразу после перехода
  через ноль (без среза по углу), волна проходит без искажений. Используется режимом
  FIRST WAVE для 2-й и следующих полуволн.

### 2. Выбор поведения на каждой полуволне — `Core/Device/device.c`, `Device_OnZeroCross()`

Вместо «вызывать `Tiristor_OnZeroCross()` только на 1-й полуволне» теперь функция
вызывается **на каждой полуволне**, а перед ней устанавливается состояние PassThrough:

```c
if(Device.State == DEVICE_TEST)
{
    /* WORK_MODE_FIRST_WAVE: 1-я полуволна срезается под углом,
       а последующие пропускаются без искажений. Тиристор запирается
       на каждом переходе через ноль, поэтому чтобы ток шёл дальше,
       его нужно вновь открывать сразу после нуля (PassThrough). */
    Tiristor_SetPassThrough((Settings.WorkMode == WORK_MODE_FIRST_WAVE) &&
                            (TestHalfWaves != 0U));

    Tiristor_OnZeroCross();

    TestHalfWaves++;
    ZeroCrossCounter++;
}
```

- Для **FIRST WAVE**: `PassThrough = (TestHalfWaves != 0U)` — 1-я волна срезается по углу,
  последующие открываются сразу после нуля.
- Для **CONTINUOUS / TIMED**: `Settings.WorkMode == WORK_MODE_FIRST_WAVE` ложно, поэтому
  `PassThrough = 0` на каждой волне — срез по углу, поведение прежнее.

### 3. Расчёт задержки открытия — `Core/Device/tiristor.c`, `Tiristor_OnZeroCross()`

При включённом PassThrough задержка после нуля минимальна (сразу открываем тиристор):

```c
uint32_t delay = Tiristor.ZeroCrossOffsetUs
               + (Tiristor.PassThrough
                  ? TIRISTOR_MIN_DELAY_US
                  : ((halfPeriod * Device_GetAngle()) / 180U));
```

- `PassThrough == 0` — прежнее поведение: задержка по заданному углу
  `offset + halfPeriod * angle / 180` (границы `TIRISTOR_MIN_DELAY_US` … `max_delay`).
- `PassThrough == 1` — открытие сразу после нуля (минимально допустимая задержка).

### 4. Страховка по каналу CH1 — `Core/Device/tiristor.c`, `Tiristor_Channel1_IRQHandler()`

Прежнее гашение после первой волны (`TIRISTOR_MODE_FIRST` отключало `CC1IE`) теперь не
срабатывает в режиме PassThrough, чтобы повторные волны могли открываться:

```c
if((Tiristor.Mode == TIRISTOR_MODE_FIRST) && !Tiristor.PassThrough)
{
    htim2.Instance->DIER &= ~TIM_DIER_CC1IE;
}
```

`TIRISTOR_MODE_FIRST` сохранён как страховка именно для первой (срезаемой) волны.

### 5. Комментарий в применении настроек — `Core/Device/settings.c`, `SETTINGS_Apply()`

Обновлены пояснения: в FIRST WAVE импульс формируется на каждой полуволне — 1-я срезается
под углом, остальные открывают тиристор сразу после нуля (управляется через
`device.c` + `PassThrough`).

## Как проверить

1. Установить **MODE = FIRST WAVE**, задать угол среза (фазу включения).
2. Запустить работу (START).
3. На осциллографе/нагрузке:
   - **1-я полуволна** — открытие с задержкой по заданному углу;
   - **2-я и последующие** — открытие сразу после перехода через ноль (без среза по углу),
     ток проходит на протяжении всего времени работы.
4. Переключить в **CONTINUOUS** и **TIMED** и убедиться, что срез по углу по-прежнему
   выполняется на каждой полуволне (прежнее поведение).
